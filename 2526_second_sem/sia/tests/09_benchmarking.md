Why is Integration Testing critical for "Build + Buy" strategies?
- To ensure software can communicate with third-party APIs
- To test the physical hardware speed of a cloud provider
- To verify that the user interface looks consistent across all pages
- To replace the need for an SLA agreement with a vendor

- To ensure the system is "fit for purpose" in a real-world environment
- To find memory leaks by running the system for 48 hours straight
- To measure the exact number of requests per second the database can handle
- To write the initial source code for a differentiator capability

In benchmarking, what does "Throughput" measure?
- The number of requests or transactions the system can handle per second
- The time it takes for a single request to receive its first byte of data
- The percentage of failed requests during a high-traffic event
- The historical uptime of a vendor's infrastructure over a year

What is the specific purpose of Soak Testing?
- To find performance degradation or memory leaks over a long period of time
- To test how the system recovers from a sudden, extreme burst of traffic
- To verify that the "Add to Cart" button works correctly for the first user
- To compare the cost of building a feature versus buying it

How does Spike Testing help in evaluating a cloud provider?
- It measures if the provider can scale up quickly to handle a viral traffic surge
- It verifies if the provider's database uses PostgreSQL or MySQL
- It confirms that the provider has "Five Nines" of historical uptime
- It ensures that the provider's API follows industry best practices for security

Why should a company measure Latency Benchmarking using P99/P95 instead of just an average?
- To ensure a consistent experience for all users, including those in the slowest percentiles
- To make the system appear faster than it actually is in marketing materials
- To reduce the cost of running automated unit tests in a CI/CD pipeline
- To find functional bugs in the application's login flow

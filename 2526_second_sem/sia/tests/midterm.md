### Problems

A development team building an appointment scheduling system for a veterinary clinic skips talking to the receptionists and vets because they assume they already understand the workflow
Insufficient user involvement

Before any details are finalized for a new online bookstore, a project manager gives the client a quick, overly optimistic estimate that the system will be entirely completed in 3 weeks
Inaccurate planning

Midway through developing a simple desk-booking system for a coworking space, stakeholders continuously request new feature additions, such as a community event board, automatic invoice generators, and a coffee machine integration
Scope creep

A written requirement for a library application states: "The system should load book profiles quickly during peak hours." A developer builds the search feature to load in 4 seconds, but the tester flags it as a defect because they expected the system to respond in under 1 second, resulting in wasted time and mismatched expectations
Ambiguous requirements

While coding a plant care guide integration for a local nursery, a developer spends three days adding an unrequested, highly advanced 3D rotating visualizer of a leaf
gold plating

## documents

Which of these most accurately describe an SRS document
A document which outlines the software requirements of a system

Which section of the SRS would you find the following statement: "The system shall allow users to log in with an email and password"
Functional Requirements

Which section of the SRS would you find the following statement: "The system must maintain 99.9% uptime"
Non-Functional Requirements

Which section of the SRS would you find the following statement: "The system must be finished within 4 weeks and the budget is capped at $15,000"
Design Constraints

Which section of the SRS would you find the following statement: "This system is designed to help local restaurants increase their online order volume by 20% within the first six months of launch"
Introduction

## testing

Why is testing important in software development?
It keeps the requirements accurate

What is considered a peer review?
Anytime someone other than the author looks at a work

What is the main problem with informal reviews
They are not structured and may miss important issues

In a formal review, what step describes the process of identifying and categorizing defects found in the work product? 
Preparation

What is one main problem with formal reviews
They can be time-consuming and may require significant resources to conduct effectively

Why would you create a prototype for a software project?
To get feedback on the design and functionality before fully developing the product

What is the main tradeoff for using more sophisticated prototyping techniques?
More sophisticated prototyping techniques take more effort

Why are conceptual tests considered "independent of implementation"
Because they focus on validating the concepts and requirements rather than the actual code

What is the main benefit of using a conceptual test
It allows you to find problems early

## lifecycles

Which software development lifecycle model is best suited for projects with well-defined requirements and a clear scope?
Waterfall

Is agile a software development lifecycle model?
False

What is the main difference between scrum and kanban in terms of how they manage work?
Scrum uses fixed-length iterations called sprints, while Kanban focuses on continuous flow without fixed iterations.

Historically, why was waterfall more useful than it is today?
Software used to be designed without continuous updates in mind

What does scrum emphasize that makes it different from other software development lifecycle models?
Transparency

## Scenario based questions on specific companies, what their goals are, and if they should buy or build

An online brand wants to add a way to buy items from their website without having to go to shoppee, should they build or buy
buy, because payment processing is not a core part of the brand
build, because they need total control over how every single cent is processed manually
buy, because it is cheaper to build it themselves in the long run
build, because brands should try to compete with Stripe and PayPal directly

A large streaming platform wants to create a content recommendation algorithm. Should they build or buy?
build, because the algorithm is a differentiator that provides a competitive advantage
buy, because it is faster to use a generic recommendation API
buy, because they should adapt their business processes to the industry's best practices
build, because they have a small team with no experience in machine learning

A local bakery wants to start an email newsletter to notify customers of daily specials. Should they build their own mailing or buy a service?
buy, because mailing infrastructure is a a common and generic tool that's easy to customize
build, because they need a highly customized email protocol for bread updates
build, because it offers infinite customizability for a simple newsletter
buy, because they want to spend more money on software than on baking

A startup needs to verify user identities to comply with government regulations. Should they build the verification logic from scratch or buy a specialized service?
buy, because specialized vendors already meet security and regulatory standards for non core systems
build, because they should never trust third parties with sensitive data even if it takes years to build
build, because verification logic is how they will differentiate themselves in the market
buy, because they want to yield control of their core value proposition to a third party

A large automotive company needs to manage payroll for 50,000 employees across multiple countries. Should they build a payroll system or buy an enterprise resource planning (ERP) module?
buy, because payroll is a standard commodity process and an ERP module is faster and less risky
build, because they need a custom payroll engine to differentiate themselves from other car manufacturers
build, because it allows for full control over global tax laws which change frequently
buy, because they want to increase the risk of their project failing

A game studio is developing an engine to achieve "never-before-seen" physics for their upcoming AAA title. Should they build the engine or license a third-party one?
build, because the unique physics engine is a differentiator that defines the product's value
buy, because it is cheaper to use Unreal Engine even if it cannot do the physics they need
buy, because they don't want to have full control over the core technology of their game
build, because they want to avoid vendor lock-in for a simple mobile puzzle game

A new ride-sharing startup needs a map interface with real-time traffic updates to launch in three months. Should they build their own mapping infrastructure or buy/license an API?
buy, because it provides a faster time to market for a capability that is not their core
build, because they have enough time in three months to map the entire world themselves
build, because they need full control over the satellite hardware
buy, because they want to lose their competitive advantage to Google Maps

An e-commerce site wants to implement a basic "Contact Us" chat widget for customer support. Should they build it from scratch or buy/use an existing service?
buy, because a chat widget is a commodity and a third-party solution is ready to deploy
build, because they need to customize the internal socket logic for a simple text box
build, because it is a key differentiator for their clothing brand
buy, because they want to increase their operational costs

A cloud provider wants to offer a "Database as a Service" feature that is marketed as significantly faster than any existing competitor. Should they build the engine or buy/resell an existing open-source solution?
build, because the performance of the engine is the core differentiator of the product
buy, because they can just use a standard database and hope it's fast enough
buy, because they want to adapt to the industry's definition of best practice for speed
build, because they want to save money by spending years on R&D

## Scenario based questions on specific companies, what their goals are, and if they should insource or outsource

A Gym wants to update their current flow for managing memberships, should they insource or outsource
outsource, because it is a non-core activity and they can access specialized skills faster
insource, because they want to ensure their trainers learn how to code the database
insource, because they need to keep the knowledge of membership flows as a strategic R&D initiative
outsource, because they want to lose control over their sensitive financial data

A banking corporation is developing a core transaction processing system with extremely high security and compliance requirements. Should they insource or outsource?
insource, because it involves core product development and requires high IP protection and control
outsource, because it is cheaper to let a third party handle highly regulated data
outsource, because they want to reduce operational costs for their most critical system
insource, because they want to scale the team size up and down every week

A startup needs to develop a proof-of-concept (POC) mobile app in 4 weeks to show to investors. Should they insource or outsource?
outsource, because a ready-to-deploy external team can accelerate delivery for an MVP
insource, because it takes less time to hire and train a full-time team than to contract a partner
insource, because they need to foster long-term knowledge retention for a throwaway prototype
outsource, because they want to ensure the culture of the startup is embedded in the POC

A software company wants to ensure that the knowledge of their codebase stays within the company. Should they insource or outsource?
insource, because it guarantees long-term knowledge retention and institutional expertise
outsource, because external parties are better at remembering how your internal code works
outsource, because it is easier to manage teams that are not embedded in your company values
insource, because they want to reduce their operational costs and overhead

A tech firm needs to scale its QA testing team temporarily for a major release next month. Should they insource or outsource?
outsource, because it allows for scalability on demand without the overhead of full-time hiring
insource, because they should hire 20 permanent employees for a one-month task
insource, because QA automation is a core strategic R&D initiative that requires full control
outsource, because they want to move slower and increase their budget

A fashion brand wants to modernize its 20-year-old legacy ERP system, a project expected to last only 12 months. Should they insource or outsource?
outsource, because they need access to specialized legacy modernization skills for a fixed-term project
insource, because they want to build a permanent department for a system they are trying to replace
insource, because it ensures the team is fully aligned with the fashion brand's seasonal values
outsource, because they want to keep the institutional expertise of the old system forever
